# Post-merge engineering audit: MUSIC

**Date:** 2026-10-10  
**Scope:** PRs [#114](https://github.com/ttm/music/pull/114), [#116](https://github.com/ttm/music/pull/116), [#118](https://github.com/ttm/music/pull/118); corrections in [#119](https://github.com/ttm/music/pull/119).

This audit distinguishes reproducible tests, mathematical cross-checks, formal ontology conformance, maintainability judgments and still-unmeasured perceptual quality. It does not claim independent clinical evidence or human listening results.

## Confirmed strengths

- The original MASS-compatible synthesis interfaces and defaults were preserved. The static filtered oscillator, offline polyphase oversampling and dynamic additive oscillator are opt-in.
- PR #114's coherent-bin FFT proxy identifies large off-harmonic energy in an unfiltered high-frequency wavetable. The filtered static-pitch route removes harmonics at or above Nyquist; the measurement is not a perceptual score.
- PR #116's 4x renderer improves agreement with a 16x high-rate reference on the tested abrupt 15 kHz gated carrier. This is one verified gated-synthesis case, not a general FM or nonlinear fidelity guarantee.
- SSTIM 0.19.0 Full-profile validation is exercised in CI. All seven built-in auditory stimulus generator *names* are covered by the restricted MUSIC adapters. The latter two have deliberate restrictions: colored noise requires named noise colors and cannot import custom modulation tables; spatial motion requires its built-in geometric tone source.
- Recorded parameters, carrier distinctions, binaural physical/perceptual presence, noise random seed, channel configuration and MUSIC program ordering are round-trippable within the described subset.
- Human singing evaluation has only a trial-preparation instrument. The package does not hold a new perceptual effectiveness finding.

## Verified audit corrections (PR #119)

1. **Dynamic pitch phase integration.** A 1 kHz to 12 kHz linear chirp over 0.1 s at 48 kHz was tested against its independent closed-form integral. The old left-endpoint phase sum ended approximately 0.72 radians behind and produced approximately 0.29 sine-wave RMS error. Trapezoidal integration is exact to floating-point tolerance when instantaneous frequency is linearly interpolated between samples. A separate analytic chirp regression was added rather than only comparing two implementations of the same numerical formula.
2. **SSTIM semantic import.** The first five-generator reader previously checked method, signal shape, carrier and perceptual presence but accepted conflicting channel modality, delivery medium, mono ear placement or missing channel/signal/rendering class assertions. Those source-level assertions are now required for executable import, with explicit negative tests. Irrelevant MUSIC-owned descriptive extensions still remain acceptable in this reader.
3. **Advanced RDF robustness.** The noise/spatial importer accepted an unbounded JSON engine-hints string and could propagate an uncaught iterator exception for missing channel duration. Bounded parameter JSON, object-type checks and explicit duration cardinality/number validation now reject such malformed input with `ValueError`.
4. **Listening preparation hygiene.** The trial generator now rejects non-finite or empty audio before amplitude equalization. It still does not perform or substitute for human rating.
5. **Seeded noise isolation.** A new test checks that a seeded MUSIC noise render does not advance NumPy's global RNG and that differing seeds change the samples.

## What is **not** established

### DSP

- Harmonic pruning based on instantaneous frequency is **not** a proof of band-limited output for arbitrary FM, vibrato or nonlinear transformations. Time-varying harmonic gains themselves create sidebands. The single global FFT proxy can miss aliases that coincide with permitted harmonic bins.
- `render_oversampled` is an offline array renderer; no streaming latency guarantee, comprehensive modulation-index benchmark or universal CPU budget has been established.
- Rich-waveform dynamic chirps now have a more accurate phase, but broad objective listening-equivalent comparisons against a high-rate reference over carrier/frequency-sweep/modulation matrices are still missing.
- Discontinuous gates cannot be preserved with infinite bandwidth; low-pass filtering deliberately changes their edges and timbre.

### SSTIM and protocol semantics

- Formal SSTIM Full-profile validation checks *ontology conformance*, not numerical waveform equivalence across independently developed audio engines.
- Precise MUSIC replay depends on MUSIC-owned `generator`, `parametersJson` and the implementation's algorithms. These do not become engine-independent simply because the graph also contains valid SSTIM terms.
- `sstim_program` is an ordered MUSIC program containing SSTIM stimulus specifications, **not** a generic SSTIM protocol converter nor evidence that a `SessionInstance` was delivered. General third-party SSTIM RDF cannot yet be executed.
- The current graph does not pin an immutable MUSIC synthesis-algorithm identity or a cross-library PRNG contract. A seed supports reproducible rendering in the tested installation, not a blanket guarantee across arbitrary future versions.
- The basic importer permits unrelated annotations; the advanced/program importers deliberately require exact known triples. This is a conservative contract, but their differing extensibility policies should be unified or documented for cross-system adoption.
- Parser-level input-size/resource limits for arbitrary Turtle documents need a separate hostile-input review. Bounded *audio output* size does not itself bound RDF parsing.

### API, science and release

- The task-oriented API guide improves discoverability, but the flat public API has not been structurally reduced. A documentation guide is not evidence of successful simplification or external adoption.
- The prepared blinded singer comparison is **not** the completed human evaluation. That remains the maintainer's work. Listening trial timing/onset matching and number of independent raters require protocol decisions before interpreting ratings.
- The current source on `master` remained at package version `1.10.0` after PR #118. A PyPI release, tagged algorithm identity, changelog and archival/release verification must be handled separately.

## Recommended decisions

1. Keep the existing MASS-compatible functions unchanged, and treat band-limited alternatives as separately characterized DSP engines.
2. Before describing general FM as anti-aliased, publish controlled short-time spectral and high-rate-reference tests spanning carriers near Nyquist, wide deviation, modulation rates, gate slopes, 44.1/48/96 kHz and latency/memory.
3. Treat SSTIM-to-MUSIC as a **restricted executable profile** until portable capability negotiation and independent cross-engine interpretation are demonstrated. Preserve MUSIC implementation hints rather than minting unsupported SSTIM terms.
4. Do not conflate the suite's 100% measured line/branch coverage with complete semantic, perceptual or security assurance.
5. Keep [#115](https://github.com/ttm/music/issues/115) and [#117](https://github.com/ttm/music/issues/117) open for the remaining technical and interoperability limits. No claim of a new human singing-quality result should be made without collected responses.

**Validation note:** The PR #119 corrections are subject to the repository's CI and documentation gates. The measured test count and statement/branch inventory are managed in `ASSESSMENT.md` and must match the tested commit.
